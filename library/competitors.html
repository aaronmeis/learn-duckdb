DuckDB — competitors, closed lab, and cloud

Date: 2026-10-10 Purpose: Add evidence to the DuckDB deep dive. Search only. No Elicit deep report was started.

Key takeaways

  • The academic anchor is still Raasveldt and Mühleisen, SIGMOD 2019. Later hits are the 2022 modularity talk, MonetDBLite (2018), and their CIDR 2020 note on embedded analytics for data science.
  • A 2026 Information Systems review benchmarks single-node SQL-on-Hadoop alternatives. Use it as a "when one node is enough" pointer, not as a DuckDB product review.
  • Elicit did not return a paper that evaluates DuckDB inside a classified or air-gapped lab. The nearby security papers are about SQLite in a trusted execution environment (Smaug 2023, BiTDB 2024). Those show the problem class. They do not certify DuckDB.
  • Exa separates three deployments. Local DuckDB never leaves the process. DuckDB plus object storage you control stays inside your network. MotherDuck is a cloud warehouse: dual execution can run part of a query in their cloud. ATTACH 'md:' is the line that leaves a closed lab.
  • MotherDuck's own architecture page and the CIDR 2024 paper (Atwal et al., p46) describe that hybrid. A secondary write-up (Markaicode) states MotherDuck is cloud-only and scoped to one AWS region per org, and points at MinIO plus dbt when residency is a hard rule. Treat the region claim as that article's wording until you confirm it on MotherDuck's current regions page.

What this does not say

DuckDB can run with no network. That is not an authorization to process classified data. A lab still approves the binary, the extensions, and the machine. No source in this pass is a government authority-to-operate for DuckDB or for MotherDuck.
