Glossary data table, 2026-10-11

NotebookLM table. Quack and DuckLake are notebook-only. They are not the concurrency contract.

Term Category Source kind Definition Caution
Volcano Engine paper Volcano refers to a traditional iterator-based query execution model where operators process data one tuple or row at a time using an open-next-close interface. Incurs high instruction overhead, function dispatch costs, and poor CPU cache locality for analytical workloads compared to vectorized execution.
DataChunk Engine docs A DataChunk is the core intermediate data structure in DuckDB representing a horizontal slice or batch of a columnar dataset composed of equal-length vectors processed together during vectorized execution. Must respect vector boundaries and capacity limits to fit within L1/L2 CPU caches; filters can create holes in chunks requiring compaction, and improper handling can cause memory corruption.
STANDARD_VECTOR_SIZE Engine docs STANDARD_VECTOR_SIZE is a system compile-time constant (typically 2048) defining the default maximum number of elements held in a single DuckDB vector or DataChunk. Altering or changing this default constant requires rebuilding the DuckDB engine from source and impacts binary compatibility and cache sizing.
morsel Operations talk A morsel is a fine-grained, fixed-size unit of data or work dynamic-first assigned to worker threads for dynamic task scheduling in morsel-driven parallel execution. Requires operators to be parallelism-aware; improper morsel sizing can cause dynamic scheduling overhead, thread starvation, or load imbalance.
pipeline breaker Engine paper A pipeline breaker is a query execution operator (such as a sort or global hash aggregate) that must consume and materialize its entire input dataset before yielding its first output row to downstream operators. Halts streaming execution, forces materialization boundaries in RAM, and can trigger high memory pressure or out-of-core disk spilling.
replacement scan Engine talk A replacement scan is a mechanism that automatically intercepts unresolved table references in SQL queries and dynamically routes or substitutes them with external files or in-memory objects like DataFrames. File scans without prior copying may lack exact optimizer statistics, and path or namespace collisions can cause unexpected recursion or execution against unintended data sources.
out-of-core Engine talk Out-of-core processing refers to execution capabilities that allow processing datasets larger than available main RAM by streaming and spilling intermediate operator state to disk. Spilling intermediate data to persistent storage incurs significant disk I/O performance penalties compared to in-memory processing.
single writer Trust talk Single writer refers to the database concurrency model and storage constraint where only a single connection, process, or thread can hold a write lock and perform write operations on a database file at any given time. Concurrent write attempts from multiple separate processes on the same persistent database file will result in lock errors or contention.
auto-install Operations docs Auto-install is a mechanism that automatically fetches, downloads, and installs missing official or community extension packages on demand when a query requires their functionality. Requires active internet connectivity, appropriate file system write permissions, and introduces dynamic dynamic-code loading security considerations.
httpfs Placement talk httpfs is an extension that enables DuckDB to read and write remote files directly over HTTP(S) and cloud object storage APIs like AWS S3. Remote file reads depend heavily on network bandwidth, API rate limits, and latency compared to local disk access.
ATTACH md: Placement docs ATTACH md: is a SQL command syntax used to mount and attach remote MotherDuck cloud database instances directly into a local DuckDB session. Requires valid authentication credentials and depends on continuous network access and cloud service availability.
dual execution Operations talk Dual execution is a hybrid query processing strategy where execution is dynamically partitioned or routed between local embedded DuckDB engines and remote cloud compute instances. Data transfer and network serialization overhead between local and cloud layers can offset performance benefits.
Quack Trust notebook-only Quack refers to an informal duck-themed utility, client tool, or protocol term used within community and testing contexts. Marked as notebook-only because available sources do not establish this term as the core transaction or concurrency contract.
DuckLake Placement notebook-only DuckLake refers to an informal or conceptual lakehouse architecture pattern and data lake integration framework used with DuckDB. Marked as notebook-only because available sources do not establish this term as the core transaction or concurrency contract.
