GLOSSARY — DuckDB

Study glossary for the DuckDB pack. Definitions follow the source ledger. They are not a claim that the study day was completed.

Definitions below are study definitions tied to the source ledger. The one-day session has not been sat, so none of these are marked as earned in practice.

Term Definition Block
DuckDB In-process analytical database. SQL runs inside the calling process. MIT license, DuckDB Foundation. [S1][S4] 1
In-process The engine and the program share one address space. There is no database server and no result-row copy across a socket. [S4] 1
Client-server The database runs in another process. Every query pays for a protocol and a copy of the result. Postgres and Snowflake work this way. [S4] 1
OLAP Few large scans, joins, and aggregates. The workload DuckDB is built for. [S4] 1
OLTP Many small row reads and writes. SQLite and Postgres are built for this. [S4] 1
Missing quadrant Embedded OLTP is SQLite. Server OLTP is Postgres. Server OLAP is a warehouse. Embedded OLAP is the corner DuckDB claims. [S4] 1
SQLite In-process OLTP. Point lookups and small writes. Not an analytical column store. [S4] 1
PostgreSQL Server OLTP and a system of record. Many writers. Use it when the database must stay correct under concurrent transactions. [S3] 1
Polars Dataframe API on one machine. Not a SQL catalog and not a multi-process database file. 2
Spark Cluster engine for data that will not fit one machine, or for a job that must survive a lost node. 7
Columnar storage Values of one column sit together. A SUM reads that column and skips the rest. [S2] 1
Row store One row's fields sit together. Good for fetching a whole row by key. Wasteful when a query names two columns of a wide table. [S2] 1
Vector One column of a batch. The execution format is a set of these vectors. [S2] 2
DataChunk A batch of aligned vectors. The default batch is 2048 tuples (STANDARD_VECTOR_SIZE). Operators run on the chunk. [S2] 2
Vectorized execution Operators process a chunk, not one row at a time, so the working values stay in cache. [S2][S5] 2
Morsel A piece of a pipeline that an idle thread takes from a queue. From the HyPer line of work, not invented in the 2019 paper. [S5] 2
Hash join Build a hash table on the smaller side, then probe with the larger side. The wrong build side is a common out-of-memory failure. [S2] 3
Spill Writing an intermediate result to disk when it does not fit in memory. A plan that cannot spill dies instead. [S2] 5
Replacement scan A scan of a registered data frame or Arrow table that stands in for a table name. [S1] 3
Predicate pushdown Filters applied inside a Parquet reader so row groups that cannot match are not decoded. [S1] 3
Zero-copy scan Reading CSV, Parquet, Pandas, or Arrow without a separate load step into a new table. [S1] 3
EXPLAIN The plan DuckDB will run. Use it before trusting a timing, especially the join build side. [S1] 3
Single writer One process may write a database file. Other processes may open it only with access_mode set to READ_ONLY. [S3] 5
Optimistic concurrency Inside the writer process, transactions proceed and conflict if they touch the same rows. This is not multi-process writing. [S3] 5
Database locked The usual tell that a second process tried to write, or that a transaction conflicted. [S3] 5
Extension Optional code loaded beside the core. It runs with the rights of the DuckDB process. [S10] 5
Auto-install The setting that fetches an extension from extensions.duckdb.org on first use. Turn it off in a closed room. [S10] 5
httpfs Extension for HTTP and S3-style reads. Not part of the zero-dependency core. [S10] 5
Iceberg Extension for Iceberg tables. Same trust rule as any other extension. [S10] 5
MotherDuck A separate cloud product. It is not local DuckDB. [S8][S9] 5
ATTACH md: The statement that connects this process to MotherDuck. After it, the query is no longer confined to the machine. [S8] 5
Dual execution MotherDuck can run part of a query locally and part in its cloud. Described in the CIDR 2024 paper. [S9] 5
Closed-lab rule Local DuckDB with no network is a deployment proposal. It is not permission to process classified data. No paper in this pack evaluates DuckDB in a classified lab. [S11][S12] 5
Volcano One row at a time. Postgres and SQLite. DuckDB passes a chunk instead. 2
STANDARD_VECTOR_SIZE The default batch of 2048 tuples. [S2] 2
Pipeline breaker Hash-join build, hash aggregate, or sort. It must see all input before it emits. 2
Exchange operator A fixed hash split across workers. One huge key stalls a worker. Morsels do not split that way. 2
Replacement scan A file path or a data frame in FROM, with no CREATE TABLE first. [S1] 3
Out-of-core Spill a join or aggregate to disk when RAM is not enough. 5
max_memory The threshold where spilling starts. 5
Flat vector Tuple i lives at offset i. 2
Dictionary vector Distinct values once, plus indexes. 2
Constant vector One repeated value for the chunk. 2
String prefix A 4-byte prefix on long strings so many comparisons skip the heap pointer. 2
Host fate A fatal error in the engine ends the host process. 5
Transaction conflict Two threads in the writer process edit the same row. 5
Parquet Columnar files scanned in place. [S1] 3
Arrow Shared memory DuckDB can scan without a copy into its own table. [S1] 3
Core versus extension SQL core stays small. Parquet, JSON, httpfs, spatial, and ICU load beside it. [S10] 5
Quack Named in the NotebookLM briefing as a client-server idea. Not the concurrency contract. [S3] 5
DuckLake Named on a slide and in the 2026 talk. It does not change one writer for a local file. [S3] 5
MonetDB and X100 The vectorized line DuckDB comes from. Morsels come from HyPer. [S7] 2
