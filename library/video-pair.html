Business Explanation

Business Explanation

DuckDB sits inside the application process and answers analytical SQL against files on that machine. These two videos exist so a reviewer can see that claim in one minute, including the job DuckDB should refuse: many people writing at the same time. The MP4s are the artifacts. This note is the map.

The claim

DuckDB is an in-process column store. A query reads the columns it names, and each operator works a batch. The default batch is 2048 values. One process may write. Many processes may read only when the file is opened read-only. Multi-user writes belong on Postgres or SQLite. Local analytics on files is the DuckDB job.

Beats

Seconds Beat
0–10 DuckDB lives in the process. It is not a server you connect to.
10–24 A row store reads the whole row. A column store reads the columns the query names.
24–40 One operator handles a batch. The default batch is 2048 values.
40–50 One writer process. Many readers only when the file is opened read-only.
50–60 Many writers: pick Postgres or SQLite. Local analytics on files: pick DuckDB.

How the two cuts differ

HyperFrames is HTML. Timing lives on data-start and data-duration. GSAP drives a paused timeline named main. npm run check passed with zero errors and six warnings: five scenes share one track, and each scene contains nested paragraphs. The render used standard quality and finished in about 73 seconds.

Remotion is React. Composition id DuckDBExplainer, package remotion@4.0.532. Five Sequence blocks cover frames 0–300, 300–720, 720–1200, 1200–1500, and 1500–1800. Motion is computed from the current frame so a seek lands on the same picture.
